# 设备与无障碍底线：桌面专属沉浸 + 移动端保底可读 + reduced-motion 平台级

「完美体验」的沉浸世界、穿越转场、GSAP 钉屏/视差很「重」，必须先定设备与无障碍底线，否则做完会出现跑不动 / 手机崩。受众含学生/教师（大量用手机）+ 历史爱好者。决策：

- **桌面**：完整沉浸——沉浸世界、穿越转场、视差、钉屏、关系图谱聚焦编排，火力集中于此。
- **移动端**：**不做任何沉浸/穿越/视差奇观**，但**保底可读不崩**——响应式布局、内容能读、导航与详情抽屉能用、不溢出。成本极低（基础响应式），保住核心教育受众。
- **reduced-motion**：从现状「做了一半」升级为**平台级一等公民**——所有沉浸/转场/滚动编排都必须有降级版，且降级后内容完整。

## Considered Options

- **桌面专属、移动端完全不投入**（手机可能溢出/读不了）：否决——学生/教师大量用手机，与「让更多人了解历史」初心冲突。
- **双端完全对等沉浸**：否决——移动端做重度穿越/视差极难且贵，会反过来削弱桌面愿景。
- **桌面专属沉浸 + 移动端保底可读**：✅ 选中。奇观桌面独享，移动端低成本保住可用。

## Consequences

- 沉浸/转场/图谱编排需从一开始就按「桌面完整 / 移动降级 / reduced-motion 降级」三态设计，而非事后补。
- reduced-motion 需平台级机制（统一 hook / wrapper），不再各组件自行决定（现状不一致：仅 Drawer/明朝两图实现）。
- 移动端是「可读基线」而非「响应式沉浸」，明确不投入移动端的重动画工程。
