# 内容深度边界与数据维护策略：有界自维护 + 沉浸优先、外链克制靠后

[ADR-0002](./0002-content-depth-model.md) 定了内容分层（L0/L1/L2 + 内容原子），但未定「自维护到多深、再深怎么办」。历史是分形、无限深的。关键认识：**瓶颈不是存储/加载**（纯文本，静态站 + Next.js 按 朝代→模块→原子 懒加载完全够，"保留数据"没问题），**而是维护可持续性、质量均匀性、范围聚焦。** 决策：

**有界自维护 + 沉浸优先、外链克制靠后。**

- **自维护范围（边界＝制度视角，而非"嫌麻烦就早外链"）**：宏观（朝代总览）→ 模块（机构 L0/L1）→ L2 深读 + 事件/人物/概念内容原子。凡「理解该制度及其制衡」所需者，**在制度视角内尽量自维护、自足**；超出制度视角者（完整人物传记、史料全文、通史细节）才不自维护。
- **深度契约**：每类原子填同一结构（是什么 / 在制度中的角色 / 1-3 个体现制度运作的关键片段 / 关联链接 / 史料引文），保证有界、质量均匀、可判断「写完」。
- **外链 = 深处的安静标识/出口，沉浸优先**：外链主要作为**可靠的史料标识/引用**而存在，**不是常态导航、不是体验的一部分**。三条原则：
  1. **尽量靠后**——把外链点推到最深的边缘；能站内讲透就**绝不早早让用户跳出**，最大化沉浸。
  2. **尽量小**——外链footprint 最小化；只在 L2 深读末尾 / 深层原子的尽头出现。
  3. **呈现克制**——以小号「史料原文 ↗ / 延伸阅读 ↗」脚注式标识出现，新标签打开；**绝不**在 L0/L1/早期/常态体验放显眼的「去站外」按钮。
- **权威源**：维基百科 / 百度百科（通识）、中国哲学书电子化计划 ctext.org（《明实录》《大明会典》等史料原文）。

## Considered Options

- **尽量自维护到底**：否决——存储不是问题，但维护近乎无限、质量难均匀、范围从「制度博物馆」漂移成「通史百科」，永远做不完。
- **浅维护（L0/L1）早外链**：否决——违背 ADR-0002「微观有料 / 深究不撞空」，且**早早把用户踢出站、沉浸断裂**（用户明确反对）。
- **有界自维护 + 沉浸优先、外链克制靠后**：✅ 选中。范围由「制度视角」封顶（维护有终点、质量均匀），范围之内尽量自足以保沉浸，外链仅作深处安静的史料标识。

## Consequences

- 维护量由**范围（制度视角）**封顶，而非由"早外链"封顶——范围内倾向自维护以保沉浸；范围外才外链。
- 外链在 UI 上必须做成**低调的引用/脚注样式**，并保证任何外链出现处、站内内容都已自足；外链不计入常态导航。
- 数据模型含「延伸阅读」外链字段（每个原子可挂权威外链），纳入 Zod 校验（至少 URL 格式与必填）。
- 「深度契约」应成为内容 schema 的一部分，由 Zod 固化（接 ADR-0002/0005 的校验链）。
